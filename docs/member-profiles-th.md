# โปรไฟล์สมาชิกและบัญชีธนาคารตอนเริ่มใช้งาน

## การใช้งาน

- มีหน้าดูสมาชิกที่ `/users/:id` แยกจากหน้าแก้โปรไฟล์ของตัวเอง แสดงรูป ชื่อ คำแนะนำตัว คะแนน รีวิวล่าสุด และข้อมูลติดต่อที่ API อนุญาต โดยไม่เปลี่ยนบัญชีหรือบทบาทของผู้ดู
- กดดูโปรไฟล์ได้จากรายละเอียดงานของผู้ว่าจ้าง/ผู้รับจ้าง หน้าติดตามงาน ผู้สมัครงาน รายละเอียดบริการ หน้าขอใช้บริการ และรายละเอียดคำขอบริการ
- กดดูบัญชีตนเองจะไปหน้าโปรไฟล์เดิม; เมื่อดูบัญชีอื่น ปุ่มย้อนกลับใช้ navigation ที่มี fallback ตามบทบาท
- อีเมลแสดงเฉพาะเจ้าของบัญชี แอดมิน หรือคู่จ้างงานหลังยืนยันเลือกผู้รับจ้าง รวมถึงงานที่ completed หรือ cancelled หลังมีผู้รับจ้างที่เลือกจริง ผู้สมัครหรือผู้ใช้คนอื่นไม่ได้รับ email จาก API
- เบอร์โทร/LINE ยังคงเปิดเฉพาะเจ้าของ/แอดมิน/คู่จ้างงานที่ยัง active ตามสิทธิ์เดิม บัญชีธนาคาร ที่อยู่ รหัสนักศึกษา และพิกัดไม่ถูกเพิ่มลงใน public profile
- อีเมลที่มีสิทธิ์เห็นมีลิงก์ mailto ทั้งในหน้าดูโปรไฟล์และหน้ารายละเอียดงานที่จ้างกันแล้ว แม้ไม่ได้ใส่ LINE

## การกรอกโปรไฟล์ครั้งแรก

ผู้ใช้ใหม่ต้องกรอกชื่อ เบอร์โทร ชื่อธนาคาร เลขบัญชี และชื่อเจ้าของบัญชี ก่อน isProfileComplete เป็น true บังคับทั้ง form และ API ไม่ใช้ schema required ทั่วไป เพราะบัญชี Google ต้องถูกสร้างได้ก่อนกรอกข้อมูล และบัญชีเดิมที่ complete แล้วไม่ต้องเริ่ม onboarding ใหม่

ข้อความกำกับ: “ขณะนี้เป็นระบบทดสอบ สามารถกรอกข้อมูลบัญชีสมมติได้ เช่น เลขบัญชี 0000000000 ไม่จำเป็นต้องใช้บัญชีจริง”

เลขบัญชีเก็บเป็นข้อความเพื่อรักษาเลขศูนย์นำหน้า ไม่ตรวจยืนยันว่าเป็นบัญชีธนาคารจริง ฟอร์มไม่ล้างค่าที่กรอกเมื่อบันทึกไม่สำเร็จ

## ตรวจสอบ

- `npm test`: 129 frontend tests ผ่าน
- `node --test tests/member-profile-backend.cjs tests/profile-avatars-backend.cjs`: 9 tests ผ่าน รวมความสัมพันธ์ของคู่จ้างงาน/บุคคลอื่น การป้องกันข้อมูลส่วนตัว และการบังคับบัญชีธนาคารเฉพาะ onboarding
- `HIRER_PREVIEW_URL=http://localhost:5173 node scripts/check-member-profiles.cjs`: 10 flow groups ผ่าน ครอบคลุมลิงก์จาก 6 หน้าและปุ่มกลับ, โปรไฟล์ของคู่จ้างงาน/บุคคลอื่น, ฟอร์มธนาคาร และการลองบันทึกซ้ำ
- ตรวจ responsive, contrast, accessible names และ touch targets ที่ 320/390/768/1440 px; ภาพตัวอย่างและผลตรวจอยู่ที่ `docs/ui-review/member-profiles/`
- ใช้ fixture accounts/API ใน Chrome และ in-memory models ใน backend tests ไม่สร้างบัญชีจริง ไม่ส่งอีเมล และไม่แก้ข้อมูลบัญชีธนาคารของผู้ใช้จริง

## อัปเดตระบบทดสอบ

Backend สำหรับลิงก์ทดสอบรันแยกจาก `npm start` ที่พอร์ต 4000 หากใช้ localhost ให้ restart backend ของผู้พัฒนาด้วยเพื่อโหลดกฎ API ใหม่

สคริปต์ `scripts/reload-share-backend.ps1` รีโหลดเฉพาะ backend ทดสอบผ่าน control endpoint ที่ฟังบน loopback และต้องมี token จาก session file ไม่หยุด supervisor/Cloudflare และทดสอบแล้วว่า URL คงเดิมหลัง reload

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\reload-share-backend.ps1
```

ไฟล์ session และ control token อยู่ใน .password-recovery ที่ถูก gitignore ไม่ต้องส่งให้ผู้ทดสอบ
