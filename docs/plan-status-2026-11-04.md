# สรุปสถานะ JangDi เทียบแผนงาน — 4 พฤศจิกายน 2569

อ้างอิง PDF “JangDi — สรุปสถานะระบบ และแผนงาน Agile (ถึงกลาง พ (3).pdf” จำนวน 12 หน้า เทียบกับโค้ดปัจจุบันและผลการทำงานในบทสนทนานี้

คำว่า “มีโค้ดแล้ว” หมายถึงพบการต่อ API/การทำงานใน repository ไม่ได้ยืนยันว่าทดสอบผ่านหน้าจอทุกกรณี หรือผ่าน Definition of Done ของทีมแล้ว

## สิ่งที่ทำเพิ่มในรอบนี้

1. ปรับหน้าการเงินผู้ว่าจ้าง/ผู้รับจ้างเป็นภาษาไทย แยกยอดสะสมกับยอดตามช่วงเวลา เพิ่มประวัติพร้อมสถานะและการเปิดรายละเอียดงาน
2. เพิ่มรายงานการเงินผู้ดูแล เลือกเดือน/วันที่ได้ แยกยอดรับ ค่าบริการแพลตฟอร์ม ค่า gateway ค่าจ้างที่ยืนยัน คืนเงิน และเงินที่ยังพักไว้ แสดงค่าธรรมเนียมที่ยังไม่ทราบเป็นรอยืนยัน
3. เพิ่ม Stripe Checkout โหมดทดสอบ ตรวจลายเซ็น webhook ยอดเงิน และป้องกันการประมวลผลซ้ำ ยังไม่ตั้งค่าบัญชี Stripe test และยังไม่ได้ทดลอง Checkout กับบัญชีโครงการ
4. เพิ่มขอคืนเงินก่อนยืนยันรับงาน แนบภาพได้ ผู้ดูแลอนุมัติ/ปฏิเสธพร้อมเหตุผลได้ ปฏิเสธแล้วคืนงานสู่ขั้นตอนเดิม อนุมัติแล้วคืนเต็มยอดรวมค่าบริการในโหมดทดสอบ
5. เปลี่ยนรูปหลักฐานจบงานจากการพึ่งไฟล์ในเครื่อง เป็นเก็บข้อมูลรูปใน MongoDB เดิม ทำให้ backend คนละเครื่องอ่านรูปเดียวกันได้เมื่อใช้ฐานข้อมูลเดียวกันและอัปเดตโค้ดทั้งสองเครื่อง
6. เพิ่มการลองโหลดรูปใหม่หลังคำขอล้มเหลว ป้องกันคำขอเก่าทับรูปใหม่ และไม่ให้ประวัติสถานะที่โหลดล้มเหลวมาขวางการดูรูป
7. ย้ายรูปเก่าเข้าฐานข้อมูลสำเร็จ 1 รายการ อีก 4 รายการไม่มีไฟล์ต้นฉบับบนเครื่องนี้ ต้องย้ายจากเครื่องที่มีไฟล์หรือให้ผู้รับจ้างส่งใหม่
8. การตรวจครั้งล่าสุด build ผ่าน และชุดทดสอบผ่านรวม 93 ข้อ (backend 85 ข้อ และตัวโหลดรูป frontend 8 ข้อ) ยังไม่ใช่ผล UAT ผ่านหน้าจอสองเครื่อง

## งานก่อนปิด MVP และงานเงินจริง

ลำดับที่เสนอให้ทำต่อเพื่อเข้าเป้าหมายในเอกสาร:

1. อัปเดต backend ทั้งสองเครื่อง ใช้ MongoDB/database เดียวกัน restart แล้วทดสอบรูปหลักฐานและ flow หลักด้วย hirer/worker/admin จริง ย้ายรูปเก่าอีก 4 รายการจากเครื่องที่มีไฟล์
2. ทำ F6 ฝั่งหน้าแอป: เชื่อม Socket หลัง login รายการแจ้งเตือน badge จากข้อมูลจริง อ่านแล้ว/อ่านทั้งหมด และทดสอบอีเมล
3. ปิดรายการ UI หน้า 12: ฟีด hirer แยกสถานะ รายละเอียดตามประเภท และรูปโปรไฟล์/navbar รวมข้อความภาษาไทยในหน้าที่ยังเป็นภาษาอังกฤษ
4. ปิดสถานะย่อยของงาน และงานหมดอายุอัตโนมัติหากคงไว้ในขอบเขต MVP รวมกำหนดวิธีให้ worker ยกเลิกงานที่รับแล้ว
5. ตั้งค่า Stripe โหมดทดสอบและทดสอบสำเร็จ/ยกเลิก/ล้มเหลว/คืนเงินกับบัญชีโครงการ ตรวจยอดและสิทธิ์ให้ครบ
6. ตรวจสิทธิ์รายละเอียดงานทั่วไป `/jobs/:id` ซึ่งยังตรวจเพียง login; รูปหลักฐานตรวจสิทธิ์แล้ว แต่ไม่ได้หมายความว่ารายละเอียดงานทุกฟิลด์มีการจำกัดครบ ตรวจสลิปโอนเงินเพิ่มเติมก่อนใช้เงินจริง และยืนยันการ rotate secrets
7. เตรียม deploy/HTTPS/env บัญชีทดสอบ test script และแบบเก็บ feedback ทดสอบตาม TC ใน PDF หน้า 9–11 ให้ครบทั้งกรณีบวกและลบ ขอเพื่อน review แล้ว merge

**Sprint 5 เงินจริงเป็นงานหลัง MVP ตาม PDF หน้า 7:** ต้องกำหนดเงื่อนไขรับชำระ/คืนเงิน จ่ายเงินจริงให้ผู้รับจ้างหลังผู้ดูแลพิจารณา หลักฐานการโอน และกติกาค่าบริการ 5–10% โค้ด Stripe test และสถานะ `released` ปัจจุบันยังไม่ใช่การโอนเข้าบัญชี worker

รายการที่เลื่อนได้ตาม PDF ได้แก่ Google Maps pin, แชทในแอป และกราฟผู้ดูแล หากทีมยืนยันขอบเขตให้ใช้งานผ่านเบอร์/LINE และรายงานตัวเลขไปก่อน

## กำหนดการและเกณฑ์ Done

ตามปฏิทินหน้า 5 วันที่ 4 พ.ย. อยู่ใน S3 (2–13 พ.ย. 2569) เป้าหมาย code freeze วันที่ 13 พ.ย. buffer 14–15 พ.ย. และ UAT 16–30 พ.ย. การเพิ่มหัวข้อ Sprint 4/5 ในไฟล์ไม่มีวันที่กำกับใหม่ จึงไม่ควรอนุมานว่าเงินจริงต้องเปิดใช้ภายใน MVP

Definition of Done หน้า 9 ยังต้องมี: ต่อ API จริง จัดการ loading/error ทดสอบสองบัญชีและ admin เพื่อน review และ merge เข้า main โดย build ผ่าน ปัจจุบันยืนยันได้เรื่องโค้ดและผลตรวจใน workspace แต่ยังยืนยัน peer review, merge, deployment และ UAT ไม่ได้
