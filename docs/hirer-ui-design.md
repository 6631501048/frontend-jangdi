# JangDi — หน้าผู้ว่าจ้าง `/hirer`

หน้าตัวอย่างสำหรับผู้ว่าจ้างที่ต้องการหาคนช่วยทำงาน ค้นหาบริการ ส่งคำขอใช้บริการ และกลับไปจัดการงานของตนเอง ใช้ Vue 3, Pinia, Vue Router และ Axios เดิม ไม่เพิ่ม UI framework

## Design system แบบสั้น

- สีหลัก `#A24936`: ปุ่มหลัก ลิงก์เน้น สถานะเลือก และวง focus; hover `#873B2B`
- สีพีช `#E5A48A`: ฐานโทนอุ่น ใช้เฉดอ่อน `#FAE5DB` กับกล่องเริ่มประกาศงานและป้ายบริการ
- สีเหลือง `#FFD65C`: ส่วนเน้น; เฉดอ่อน `#FFF4CF` กับประวัติคำขอและสถานะรอตอบรับ
- พื้นการ์ด `#FFFFFF`, พื้นหน้า `#FCFAF8`, ข้อความ `#100E04`, ข้อความรอง `#635B53`
- ตัวอักษร Noto Sans Thai พร้อม system fallback; เนื้อหา 16px, label/action 14px, เวลา 13px; ใช้ rem รองรับการปรับขนาดข้อความ
- ระยะห่างอิง 4/8px, การ์ดมุม 20px, ปุ่มมุม 12px, พื้นที่สัมผัสอย่างน้อย 44px
- เดสก์ท็อปแสดงการ์ดสองคอลัมน์ มือถือแสดงหนึ่งคอลัมน์ ตัวกรองตัดขึ้นบรรทัดใหม่แทนการล้นหน้าจอ

## พฤติกรรม

ใช้ AppTopBar, AppRoleDrawer และ UserAvatar เดิม หน้านี้เป็นต้นแบบที่ขยายเป็น [design system ร่วมทั้งแอป](ui-design-system.md) แล้ว โดยแยก CSS ของฟีดไว้ใน `src/styles/marketplace.css` และใช้ Noto Sans Thai เป็นฟอนต์หลักของทุกหน้า

คง endpoint, ข้อมูลคำขอ, เงื่อนไขซ่อนบริการเต็ม/หมดเวลา/รับคำขอแล้ว และงานที่ไม่ได้เปิดรับสมัคร รวมถึง polling ทุก 10 วินาที ปุ่มรับบริการ รายละเอียด ประกาศงาน และประวัติคำขอเชื่อมไป route เดิม

ฟีดหน้าแรกของทั้งผู้ว่าจ้างและผู้รับจ้างซ่อนประกาศงานและประกาศบริการที่บัญชีปัจจุบันเป็นผู้โพสต์ ตรวจจากรหัสบัญชีแทนชื่อ และยังจัดการประกาศของตนเองได้ในหน้างาน/บริการของฉัน

เพิ่มปุ่มล้างตัวกรอง ปุ่มลองโหลดใหม่ label ค้นหา aria-pressed ของตัวเลือก aria-expanded ของหมวดหมู่ aria-busy ระหว่างโหลด และ skip link ข้ามไปเนื้อหา แสดงสถานะพร้อมข้อความเสมอ

ไม่แสดงผลลัพธ์เก่าในระหว่างโหลดหรือโหลดผิดพลาด เพื่อไม่ให้เข้าใจว่าเป็นรายการจากคำค้นล่าสุด

## การตรวจและภาพตัวอย่าง

ภาพใน [ui-review](ui-review/) ใช้ข้อมูลจำลองใน Chrome profile แยก ไม่มีบัญชีจริง ไม่มีการส่งคำขอจ้างหรือชำระเงินจริง ข้อมูลจำลองอยู่เฉพาะสคริปต์ตรวจ ไม่อยู่ในหน้าแอป

- [ภาพเดสก์ท็อป](ui-review/hirer-1440.png)
- [ภาพมือถือ](ui-review/hirer-390.png)
- [ภาพสถานะไม่มีประกาศ](ui-review/hirer-empty-390.png)
- [ผลตรวจ responsive และ contrast](ui-review/checks.json)

รันซ้ำด้วย `node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 5175 --strictPort` แล้วเปิดอีก terminal รัน `node scripts/check-hirer-ui.cjs` สคริปต์ใช้ Chrome ที่ติดตั้งใน Windows และ ws ซึ่งมีอยู่ใน dependencies ปัจจุบัน ตั้งค่า `CHROME_PATH` และ `HIRER_PREVIEW_URL` ได้หากใช้ตำแหน่งอื่น

ตรวจความกว้าง 320, 375, 390, 768, 1024, 1440px, พื้นที่ปุ่ม, ขยายข้อความ 200%, focus และ Enter, การค้นหา/หมวดหมู่/ล้างตัวกรอง, pagination, loading/error/retry/empty, route ปุ่ม และสีข้อความที่ระบุใน checks.json

ข้อจำกัด: เป็นการตรวจ UI กับ API response จำลองและชุดทดสอบเดิม ไม่ใช่การยืนยัน flow ส่งคำขอหรือชำระเงินกับ backend จริงทั้งหมด และไม่ใช่ accessibility audit ครบทุกหน้า
