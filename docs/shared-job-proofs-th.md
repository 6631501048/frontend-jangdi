# ดูรูปหลักฐานจาก backend คนละเครื่อง โดยไม่เพิ่มบริการ cloud

สาเหตุเดิมคือ MongoDB เก็บเพียง `completionProofUrl` แต่ไฟล์อยู่ใน `uploads/job-proofs` ของเครื่องที่ผู้รับจ้างส่งรูป อีกเครื่องจึงเห็นข้อมูลงานแต่หาไฟล์ไม่พบ

โค้ดใหม่เก็บรูปจริงใน MongoDB เดิมพร้อมสถานะงาน โดยเก็บได้หนึ่งรูปต่องานและคงข้อจำกัด 5 MB รองรับ JPEG, PNG และ WebP ไม่ต้องติดตั้ง storage เพิ่ม

ทั้งสองเครื่องต้องใช้ backend โค้ดใหม่ และ `MONGO_URI` ต้องชี้ฐานข้อมูลเดียวกัน รวมชื่อ database ด้วย จากนั้น restart backend และ frontend

รูปยังโหลดผ่าน `GET /api/jobs/:id/completion-proof` พร้อม token เฉพาะเจ้าของงาน ผู้รับจ้างที่ถูกเลือก และผู้ดูแลจึงดูได้ ข้อมูลรูปไม่ถูกแนบไปกับรายการงานหรือ JSON รายละเอียดงาน

## รูปที่ส่งใหม่

ส่งหรือเปลี่ยนรูปแล้วจะเก็บในฐานข้อมูลทันที ไม่ต้องคัดลอกโฟลเดอร์ `uploads` ระหว่างเครื่อง เมื่อผู้ว่าจ้างยืนยันรับงาน ระบบตรวจรูปจากฐานข้อมูลด้วย

## ย้ายรูปเก่า

บนเครื่องที่ยังมีไฟล์รูปเดิม ให้รันจากโฟลเดอร์ `backend`:

```sh
node scripts/migrate-job-proofs.js --dry-run
```

รายการ `ready` คือไฟล์ที่ย้ายได้ ตรวจแล้วจึงรัน:

```sh
node scripts/migrate-job-proofs.js --apply
```

คำสั่งคัดลอกข้อมูลรูปเข้าฐานข้อมูลโดยไม่ลบไฟล์ต้นฉบับ และไม่เขียนทับรูปที่เปลี่ยนระหว่างย้าย รันซ้ำได้ หากรูปกระจายอยู่หลายเครื่อง ให้รันบนแต่ละเครื่องที่มีไฟล์เดิม ข้อความ `file-on-another-machine-or-missing` หมายถึงเครื่องนั้นไม่มีไฟล์ของรายการดังกล่าว

หากไม่มีไฟล์เดิมแล้ว ให้ผู้รับจ้างเปลี่ยนรูปและส่งใหม่ก่อนผู้ว่าจ้างยืนยันรับงาน

## การทดสอบ

- ทดสอบผู้รับจ้างส่งรูป แล้วให้ backend ฝั่งผู้ว่าจ้างใช้โฟลเดอร์รูปที่ไม่มีไฟล์ โดยยังอ่านรูปและยืนยันรับงานจากฐานข้อมูลได้
- ทดสอบสิทธิ์เจ้าของงาน/ผู้รับจ้าง/บุคคลอื่น และการเปลี่ยนรูปพร้อมกับยืนยันงาน
- ทดสอบโหลดรูปครั้งแรกล้มเหลวแล้วลองใหม่ การป้องกันผลลัพธ์เก่าทับรูปใหม่ และการคืนทรัพยากรเมื่อออกจากหน้า

การใช้ฐานข้อมูลเดิมทำให้พื้นที่ฐานข้อมูลเพิ่มตามรูปที่เก็บ แต่ไม่ต้องเพิ่มบริการ cloud หรือบัญชี storage ใหม่
