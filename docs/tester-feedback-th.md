# รายละเอียดเพิ่มเติมไม่บังคับ และความคิดเห็นผู้ทดสอบ

## โพสต์งานของผู้ว่าจ้าง

ช่อง “รายละเอียดงานเพิ่มเติม” เปลี่ยนเป็นไม่บังคับ เอาเงื่อนไข notes ออกจากการผ่านขั้นตอนที่ 2 และเอา required ออกจาก textarea ผู้ใช้จึงข้ามไปตรวจทานและส่งงานได้เมื่อข้อมูลจำเป็นอื่นครบ

API และ Job model รองรับ notes ที่ไม่ระบุอยู่แล้ว จึงไม่เปลี่ยนกฎของข้อมูลหลัก เช่น ชื่องาน รายละเอียดหลัก ค่าจ้าง วันเวลา และตำแหน่ง และไม่ต้องแก้โพสต์เก่า

## ส่งความคิดเห็น

- แถบด้านข้างของทั้งผู้ว่าจ้างและผู้รับจ้างมีเมนู **ส่งความคิดเห็น** ไปที่ `/feedback`
- เลือกความคิดเห็นทั่วไป/ปัญหาการใช้งาน/ข้อเสนอแนะ และกรอกข้อความ 1–2000 ตัวอักษร
- แนบเฉพาะ pathname ของหน้าที่เข้ามาจากเมนู ไม่เก็บ query string หรือ hash ซึ่งอาจมี token
- แสดงข้อความส่งสำเร็จเมื่อ API บันทึกแล้วเท่านั้น หากส่งไม่สำเร็จเก็บข้อความไว้เพื่อให้ลองใหม่ และป้องกันกดส่งซ้ำขณะรอ
- ความคิดเห็นเก็บใน TesterFeedback แยกจาก Feedback ที่เป็นรีวิวคู่จ้างงาน ไม่มีการส่งอีเมลออกนอกระบบ

## ผู้ดูแลระบบ

เมนู **ความคิดเห็นผู้ทดสอบ** ไปที่ `/admin/tester-feedback` แสดงชื่อ/อีเมลผู้ส่ง บทบาท ประเภท ข้อความ วันที่ และหน้าที่เกี่ยวข้อง กรองทั้งหมด/ยังไม่ได้อ่าน/อ่านแล้ว มีการแบ่งหน้าและทำเครื่องหมายอ่านแล้วได้ กดรีเฟรชเพื่อรับรายการล่าสุด

สิทธิ์อ่านและทำเครื่องหมายอ่านถูกบังคับที่ API ด้วย protect + adminOnly ผู้ใช้ทั่วไปไม่สามารถเปิดรายการความคิดเห็นของผู้อื่นได้ ข้อความแสดงผ่าน interpolation เพื่อไม่รัน HTML/script ที่อาจอยู่ในความคิดเห็น

API:

- POST /api/tester-feedback — ต้องล็อกอิน; ระบุ author/role จากบัญชีใน request ไม่เชื่อค่าจาก body; จำกัด 10 คำขอต่อ 10 นาทีต่อบัญชีตาม rate limiter ของโปรเจกต์
- GET /api/admin/tester-feedback?status=all|new|read&page=1 — เฉพาะแอดมิน หน้าละ 20 รายการ และปรับหน้าที่เกินขอบเขตกลับหน้าสุดท้าย
- PATCH /api/admin/tester-feedback/:id/read — เฉพาะแอดมิน การเรียกซ้ำคงเวลาอ่านครั้งแรก

ไฟล์ backend ใหม่: src/models/TesterFeedback.js, src/controllers/testerFeedback.controller.js, src/routes/testerFeedback.routes.js, src/routes/adminTesterFeedback.routes.js และลงทะเบียนใน src/routes/index.js

## ตรวจสอบ

- Frontend tests 135 ผ่าน รวมกรณีโพสต์งานพร้อม notes ว่าง ส่งความคิดเห็นสำเร็จ/ล้มเหลว/ป้องกันส่งซ้ำ และแอดมินทำเครื่องหมายอ่านแล้ว
- Backend tests 12 ผ่าน (tester-feedback + member-profile) รวมสิทธิ์ anonymous/member/admin, validation, pagination, rate limit, idempotent read และ Job API ที่ไม่ส่ง notes
- Chrome ผ่าน 6 flow groups ทั้ง localhost และไฟล์ build บนลิงก์แชร์ โดยใช้ API/บัญชี/พิกัดจำลอง ไม่สร้างงานหรือความคิดเห็นทดสอบในฐานข้อมูลจริง
- ตรวจ responsive, contrast, accessible names และขนาดเป้าหมายกดที่ 320/390/768/1440 px
- ตรวจ API จริงจากภายนอก: POST ความคิดเห็นและ GET รายการของแอดมินตอบ 401 เมื่อไม่ล็อกอิน
- ตรวจ MongoDB แบบอ่านอย่างเดียว: collection testerfeedbacks และ index status/createdAt พร้อมใช้งาน ขณะตรวจไม่มีความคิดเห็นทดสอบหลงเหลือ
- Build ผ่าน และรีโหลด backend ทดสอบผ่าน control endpoint โดยไม่หยุด Tunnel หรือเปลี่ยน URL

หากรันผ่าน localhost ของผู้พัฒนา ให้ restart backend ที่พอร์ต 4000 เพื่อโหลด routes/model ใหม่ ส่วนลิงก์แชร์อัปเดตแล้วและรีเฟรชเว็บได้ตามปกติ
