# ตรวจหน้ารายการงานทั้งสองบทบาท

ตรวจวันที่ 24 พฤศจิกายน 2026 กับ API ที่เปิดจริงที่ localhost:4000 และหน้า `/hirer`, `/worker/feed` ที่ localhost:5173

## ข้อมูลจริงที่พบ

- GET `/api/jobs` ตอบ 200 และส่งงาน waiting 2 รายการ ตรงกับจำนวนสถานะ waiting ในฐานข้อมูล
- GET `/api/service-posts` ตอบ 200 และส่ง 0 รายการ ตรวจฐานข้อมูลแบบอ่านอย่างเดียวพบ ServicePost active 7 รายการ แต่หมดช่วง availabilityEnd แล้วทั้งหมด จึงถูกซ่อนตามเงื่อนไข API
- ประกาศของตัวเองถูกซ่อนจากหน้าแรกทั้งสองบทบาทตามข้อกำหนดเดิม จึงอาจเห็นงานน้อยกว่าจำนวนที่ API คืน โดยยังดูประกาศตัวเองในหน้าจัดการได้
- ไม่นำงานที่ assigned/completed/cancelled/pending_review/rejected มาแสดงเป็นงานเปิดรับ

## ข้อผิดพลาดที่ยืนยันและแก้

1. ค้นด้วยชื่อผู้ประกาศแล้วงานหาย: API เดิมค้นแค่ title/description แม้หน้าเว็บระบุว่าค้นชื่อได้ แก้ API ให้ค้นชื่อผู้ประกาศด้วย
2. อักขระ `[` ทำให้ GET jobs ตอบ 500: API เดิมตีความคำค้นเป็น regular expression โดยตรง แก้ให้เป็นคำค้น literal และตรวจรูปแบบ/ความยาว
3. API คืนงานที่ตรง title แต่ frontend กรองทิ้งเมื่อ description ต่างกัน: เพิ่ม title ในข้อมูลและใช้ตัวกรองค้นหาร่วมกันทั้งสองบทบาท
4. ฝั่งผู้ว่าจ้างขาดหมวด errands: เพิ่ม “งานจิปาถะ” ให้ตรงกับผู้รับจ้าง
5. ฝั่งผู้รับจ้างไม่อัปเดตงานระหว่างเปิดหน้า: เพิ่ม refresh ทุก 10 วินาทีแบบเดียวกับ hirer และให้ทั้งสองหน้าล้างข้อผิดพลาดเดิมหลัง refresh สำเร็จ
6. สถานที่บริการที่ไม่ใช่ delivery หายฝั่ง worker: ใช้ locationLabel ตามประกาศ

## หลักฐานตรวจสอบ

- ก่อนแก้: API จริงค้นชื่อผู้ประกาศที่มีงาน 2 รายการได้ 0; ค้น `[` ได้ HTTP 500
- หลังแก้: เรียก controller ที่ติดตั้งแล้วกับฐานข้อมูลจริงแบบอ่านอย่างเดียว ค้นชื่อได้ 2 รายการ และค้น `[` ได้ HTTP 200
- Backend regression 5 tests: ก่อนแก้ผ่าน 1/5 หลังแก้ผ่าน 5/5
- Frontend `npm test`: ผ่าน 77 tests; `npm run build`: ผ่าน
- [Browser checks](ui-review/feed-audit/checks.json): ผ่าน 10 กลุ่ม ครอบคลุมทั้งสองบทบาท การซ่อนของตัวเอง สถานะ/วันหมดอายุ/capacity การค้นหา หมวดหมู่ pagination detail links โหลดล้มเหลว/retry/refresh และ responsive/accessibility ที่ 320/390/768/1440px
- นำข้อมูลจาก public API จริงมาใช้เป็น snapshot ใน browser fixture และตรวจทั้งบัญชีจำลองของผู้อื่นกับเจ้าของงาน โดยไม่ใช้ token บัญชีจริงและไม่ส่งคำขอเปลี่ยนข้อมูล

ภาพทดสอบใช้ข้อมูลจำลอง: [hirer](ui-review/feed-audit/hirer-390.png), [worker](ui-review/feed-audit/worker-390.png)

หลังเปลี่ยน controller ต้อง restart backend ที่รันด้วย `npm start` ในเทอร์มินัล เพื่อให้ API ที่เปิดอยู่ใช้โค้ดค้นหาล่าสุด ไม่ได้เปิด backend เพิ่มเบื้องหลัง การตรวจนี้ไม่เปลี่ยนงาน วันหมดอายุ หรือสถานะประกาศในฐานข้อมูล
