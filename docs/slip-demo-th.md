# Sprint 5 — โอนและตรวจสลิปจำลอง

ใช้ฐานข้อมูลเดิม ไม่ต้องตั้ง Stripe key/webhook และไม่มีการโอนเงินจริง ข้อมูลบัญชีที่แสดงเป็นบัญชีตัวอย่างเท่านั้น

## เริ่มทดสอบ

1. อัปเดต backend/frontend เป็นโค้ดเดียวกันทุกเครื่อง และ restart ทั้งสองส่วน ใช้ MongoDB database เดียวกันที่รองรับ transaction เช่นเดียวกับการยืนยันงานเดิม
2. เตรียมบัญชี hirer, worker และ admin พร้อมรูปสลิปตัวอย่าง JPEG/PNG/WebP ไม่เกิน 2 MB ต่อภาพ
3. Hirer โพสต์และเลือก worker หรือส่งคำขอจ้าง Service Post แล้ว worker ตอบรับ ระบบสร้างรายการ **รอชำระเงิน** ในโหมด `slip_demo`
4. Hirer เปิด “ดูการชำระเงินและสลิปจำลอง” ตรวจยอด เลือกรูป แล้วกด “ยืนยันโอนจำลองและส่งสลิป” รายการจะเป็น **รอตรวจสลิป** และ worker ยังเริ่มงานไม่ได้
5. Admin เปิด “การเงินและคืนเงิน” → “รอตรวจสลิป” กดดูรายละเอียด เปิดรูป ตรวจยอด แล้วอนุมัติหรือปฏิเสธพร้อมเหตุผล หากปฏิเสธ hirer ส่งรูปใหม่ได้
6. หลังอนุมัติ เงินเป็น **พักเงินรองานเสร็จ** และ worker เริ่มงาน/ส่งรูปหลักฐานได้
7. Hirer ตรวจหลักฐานแล้วกดยืนยันรับงาน งานเสร็จ แต่เงินเป็น **งานเสร็จ รอจ่ายค่าจ้าง** ยังไม่นับว่า worker ได้รับค่าจ้างในโหมดสลิปนี้
8. Admin เปิดแท็บ “งานเสร็จ รอ admin จ่ายค่าจ้าง” ระบุยอดและเลขอ้างอิง พร้อมแนบสลิปจ่ายจำลองและหมายเหตุ แล้วกดยืนยัน ระบบจึงบันทึก **จ่ายแล้ว** พร้อมวันที่จ่าย Worker และ hirer ดูสลิปได้จากหน้าการเงินและหน้างานของตน

## คืนเงิน

- ก่อนยืนยันรับงาน hirer กดขอคืนเงินและส่งเหตุผล/หลักฐาน
- Admin ปฏิเสธแล้วงานและเงินกลับสู่ขั้นตอนเดิม
- Admin อนุมัติแล้วจะเป็น **อนุมัติแล้ว รอสลิปคืนเงิน** ยังไม่ถือว่าคืนสำเร็จ
- Admin แนบสลิปคืนจำลองพร้อมยอดเต็ม เลขอ้างอิง และหมายเหตุ จึงบันทึกคืนสำเร็จและยกเลิกงาน
- คืนเต็มยอดรวมค่าบริการ เช่น ค่าจ้าง 100 + ค่าบริการ 5 = คืน 105 บาท ไม่มีค่า gateway ในการจำลอง

## กติกาค่าบริการ

เริ่มต้น 5% อ่านจาก backend ผ่าน `/payments/config` หากตั้ง `ESCROW_FEE_PERCENT_MIN` ใน `backend/.env` ให้เป็นตัวเลข 5–10 จะใช้ค่านั้นกับรายการใหม่ รูปแบบคำนวณยังคงบวกค่าบริการจากค่าจ้างฐาน ไม่หักจากค่าจ้าง worker ส่วนค่าบริการเพิ่มเติมของงานส่งของคงตามยอดที่แยกในงาน

ตัวอย่าง: ค่าจ้าง 100 บาท ค่าบริการ 5% ผู้ว่าจ้างชำระ 105 บาท ผู้รับจ้างรับ 100 บาท

การเปลี่ยนอัตราไม่แก้รายการ Payment ที่สร้างไว้แล้ว หน้าชำระเงินใช้ยอดที่บันทึกกับรายการนั้นเป็นหลัก

## การเก็บข้อมูลและป้องกันข้อผิดพลาด

- สลิปเก็บเป็นข้อมูลภาพส่วนตัวใน MongoDB เดิม โดยแยกสลิปขาเข้า จ่ายค่าจ้าง และคืนเงิน
- รูปไม่ถูกแนบใน JSON รายการการเงิน โหลดผ่าน API ที่ตรวจสิทธิ์เจ้าของรายการ/คู่สัญญา/admin เท่านั้น
- ตรวจชนิดภาพจากข้อมูลไฟล์จริงและจำกัดขนาด ไม่เปิดไฟล์ SVG
- ผลตรวจผูกกับเวอร์ชันรูป admin ที่เปิดรูปเก่าจะอนุมัติรูปใหม่แทนไม่ได้
- ตรวจสิทธิ์และสถานะก่อนรับไฟล์ และตรวจซ้ำใน transaction ตอนบันทึก
- ป้องกันการอนุมัติซ้ำ จ่ายซ้ำ และคืนซ้ำ เก็บผู้ดำเนินการ เวลา เหตุผล และประวัติการตรวจสลิป
- ยืนยันงานไม่ใช่จ่ายค่าจ้าง รายงานแยกวันยืนยันงานออกจากวันที่บันทึกจ่าย
- ยอดรอตรวจสลิปไม่นับเป็นยอดรับเงิน ยอดรอจ่ายไม่หักจากเงินคงเหลือจนกว่าจะบันทึกสลิปจ่าย

## ข้อมูลเดิมและ Stripe

รายการ `demo` เก่าที่ยัง pending สามารถแนบสลิปแล้วเปลี่ยนเข้าสู่ flow ใหม่ได้ หลังตรวจรับงานทุกรายการจะรอ admin จ่ายพร้อมสลิป ส่วนรายการ released จาก flow เก่าโดยไม่มีหลักฐานจ่าย ให้ใช้สคริปต์ตรวจและแก้ข้อมูลตาม [คู่มือการเงิน](payments-th.md) รายงาน worker จะไม่นับรายการที่ยังไม่มีสลิปและ paidAt เป็นเงินรับแล้ว

Stripe test รับเงินจาก hirer ผ่านบัตรหรือ QR โดยไม่ต้องแนบสลิป ยืนยันเงินด้วย webhook หรือการตรวจ Stripe จาก backend โดยตรง จากนั้นใช้ flow รอ admin จ่ายค่าจ้างพร้อมสลิปเช่นเดียวกัน ส่วน refund ของ Stripe จะคืนผ่าน API ก่อน แล้ว admin แนบหลักฐานจาก Stripe ภายหลัง ห้ามโอนคืนซ้ำ รายละเอียดและค่าธรรมเนียม mock อยู่ใน [คู่มือการเงิน](payments-th.md)

ยังต้องทดลองผ่านหน้าจอจริงด้วยสามบัญชี โดยเฉพาะการอัปโหลดจากคนละเครื่อง การตรวจภาพ และการแสดงรายงานหลังจ่าย/คืนเงิน
