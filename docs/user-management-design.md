# หน้า User management ของ JangDi

ปรับหน้า `/admin/users` จากรายการแนวตั้งและปุ่มจัดการท้ายหน้า เป็นพื้นที่ดูแลสมาชิกที่เห็นภาพรวม ค้นหาบัญชี และตรวจรายละเอียดก่อนดำเนินการ

## Design system แบบย่อ

- ใช้ Noto Sans Thai, สีแบรนด์ `#a24936`, พื้น canvas เดิม, การ์ดสีขาว เส้นขอบอุ่น และมุมโค้ง 12–20px
- เขียว = ใช้งานปกติ เหลือง = คำเตือน แดง = ระงับ พร้อมข้อความและจุดสถานะ ไม่อาศัยสีอย่างเดียว
- จำนวนสรุปกดเพื่อกรองได้ ช่องค้นหาค้นชื่อ/อีเมล/รหัสนักศึกษา และตัวกรองแยกบทบาทปัจจุบันกับสถานะบัญชี
- ตาราง desktop 4 คอลัมน์ และแผงรายละเอียดด้านข้าง; mobile เปลี่ยนแถวเป็นการ์ด เลือกแล้วเลื่อนไปแผงรายละเอียดด้านล่าง
- ปุ่มและตัวควบคุมเป้าสัมผัสอย่างน้อย 44px, focus มองเห็นได้ และข้อความย่อยอย่างน้อย 12px

## การทำงานและ API

GET `/admin/users` เดิมคืนรายชื่อสมาชิกทั้งหมดและไม่แบ่งหน้า server จึงใช้ snapshot เดียวสำหรับตัวเลขสรุป การค้นหา ตัวกรอง และ pagination ฝั่ง client (10 บัญชี/หน้า) เพื่อไม่ให้ตัวเลขผสมข้อมูลจากคนละเงื่อนไข รายชื่อเรียงตาม API ซึ่งใหม่ก่อน ไม่มีสถิติหรือ trend สมมติ

เลือกบัญชีด้วยปุ่มที่ใช้งานได้ด้วยคีย์บอร์ด แสดงชื่อ อีเมล รหัสนักศึกษา บทบาทปัจจุบัน การยืนยันอีเมล วันเข้าร่วม และ moderationHistory ที่ backend ส่งมา เปลี่ยนตัวกรองแล้วล้างการเลือกเพื่อไม่ให้จัดการบัญชีที่อยู่นอกบริบทโดยไม่ตั้งใจ

การเตือน ระงับ คืนสถานะยังใช้ POST `/admin/users/:id/suspend` กับ `{action, reason}` ตามเดิม ต้องยืนยันและระบุเหตุผล 5–500 ตัวอักษร ไม่ให้จัดการบัญชีตัวเอง/ผู้ดูแลหรือส่งสถานะซ้ำ และเก็บข้อผิดพลาดไว้ในหน้าให้ลองใหม่ หลัง POST สำเร็จโหลดประวัติจาก server ใหม่ หากโหลดซ้ำล้มเหลวจะแจ้งว่าเปลี่ยนสถานะสำเร็จแต่ประวัติยังไม่อัปเดต ไม่สรุปว่าคำสั่งล้มเหลวทั้งรายการ

## ผลตรวจ

- `npm test`: 101 tests ผ่าน รวมการค้นหา/กรอง/pagination, เหตุผลและ API เดิม, protected accounts, ยกเลิก, failure/retry และ POST สำเร็จแต่ refresh ไม่สำเร็จ
- `npm run build`: ผ่าน
- [Browser checks](ui-review/user-management/checks.json): 6 กลุ่มผ่าน ครอบคลุม 320/390/768/1024/1440px, no overflow, contrast, ชื่อ controls, เป้าสัมผัส, Enter เปิดรายละเอียด/คืน focus และ moderation ทั้งสามสถานะ
- ใช้ API/สมาชิกจำลอง ไม่มีการเปลี่ยนสถานะ ส่งคำเตือน หรือระงับบัญชีจริง
- ขอบเขตการแบ่งหน้าเป็น client ตาม API ปัจจุบัน หากเปลี่ยน API เป็น server pagination ในอนาคต ต้องเพิ่ม summary totals จาก server ควบคู่กัน
